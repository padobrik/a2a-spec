a2a-spec finds the fields that one agent reads from another agent. It tests these fields in CI. The tests use recorded outputs, so they make no LLM calls and need no API keys.

## The problem

Agent A sends data to agent B. You change the prompt of agent A, and its output changes. For example, agent A now sends `urgency` instead of `priority`.

Agent B reads `priority` with a default value. It does not stop with an error. It gives a wrong result, and no test fails.

## What a2a-spec does

1. It reads the code of agent B and finds the fields that agent B uses.
2. It records the output of agent A one time and saves it as JSON files in git.
3. It tests the recorded output against the fields that agent B needs. You run these tests in pytest or in CI.

```
agent A ──── output ────> agent B
   │                         │
a2aspec record          a2aspec infer
   │                         │
snapshots (JSON)          spec (YAML)
   └───────> a2aspec test or pytest ───────> pass / fail
```

## Terms

| Term | Meaning |
|---|---|
| Producer | The agent that sends the data. |
| Consumer | The agent that receives the data. |
| Spec | A YAML file. It gives the fields that the consumer needs from the producer. |
| Snapshot | A JSON file. It contains one recorded input and output of the producer. |
| Scenario | A named input for the producer. |
| Adapter | A small Python object. a2a-spec uses it to call your agent. |

## Get started

You need Python 3.11 or later and a git repository.

This example uses two agents. The producer `triage_agent` classifies a message. The consumer `resolution_agent` uses that result.

```python
# agents/triage.py
async def triage_agent(data: dict) -> dict:
    text = data["message"].lower()
    category = "billing" if "charge" in text else "general"
    return {"category": category, "priority": "high" if "urgent" in text else "low"}
```

```python
# agents/resolution.py
async def resolution_agent(ticket: dict) -> dict:
    escalate = ticket.get("priority", "low") == "high"
    return {"reply": f"We are checking your {ticket['category']} issue.", "escalate": escalate}
```

**1. Install a2a-spec.**

```bash
pip install a2a-spec
```

**2. Create the project files.**

```bash
a2aspec init
```

This command creates `a2a-spec.yaml` and the `a2a_spec/` directory.

**3. Remove the example spec and the example scenario.**

```bash
rm a2a_spec/specs/example-spec.yaml a2a_spec/scenarios/example-scenarios.yaml
```

**4. Add the producer to `a2a_spec/adapters/__init__.py`.**

```python
from a2a_spec import FunctionAdapter
from agents.triage import triage_agent

ADAPTERS = {
    "triage-agent": FunctionAdapter(fn=triage_agent, agent_id="triage-agent", version="1.0"),
}
```

**5. Add inputs for the producer to `a2a_spec/scenarios/support.yaml`.**

```yaml
scenarios:
  - name: double_charge
    input:
      message: "I was charged twice. This is urgent."
  - name: question
    input:
      message: "How do I change my address?"
```

**6. Record the output of the producer.**

```bash
a2aspec record
```

The command calls the producer one time for each scenario:

```
    PASS triage-agent / double_charge recorded
    PASS triage-agent / question recorded
[done] 2 snapshots saved to ./a2a_spec/snapshots
```

**7. Make the spec from the code of the consumer.**

```bash
a2aspec infer --producer triage-agent --consumer resolution-agent \
  --source agents/resolution.py:resolution_agent
```

The command writes `a2a_spec/specs/triage-agent-to-resolution-agent.yaml`:

```yaml
# Generated by 'a2aspec infer' from agents/resolution.py:resolution_agent and 2 triage-agent snapshot(s). Review before committing.
#   priority: required, read at line 2
#   category: required, read at line 3
spec:
  name: triage-agent-to-resolution-agent
  producer: triage-agent
  consumer: resolution-agent
  structural:
    type: object
    required: [priority, category]
    properties:
      priority: {type: string}
      category: {type: string}
```

Read the spec before you commit it. If the command shows a `WARN` line, read [Limits](#limits).

**8. Run the tests.**

```bash
a2aspec test
```

```
PASS triage-agent-to-resolution-agent / double_charge
PASS triage-agent-to-resolution-agent / question
  2 passed  (total: 2)
```

**9. Commit the files.**

```bash
git add a2a-spec.yaml a2a_spec agents
git commit -m "test: add agent contracts"
```

The committed snapshots are the baseline for the next steps.

## Adapters — Wrap Any Agent

a2a-spec is **framework-agnostic**. Adapters wrap your agents so the framework can call them during recording and testing.

### Plain async functions

```python
from a2a_spec import FunctionAdapter

async def my_triage_agent(input_data: dict) -> dict:
    # Your agent logic (calls OpenAI, Anthropic, local model, etc.)
    return {"category": "billing", "summary": "Customer reports duplicate charge", "confidence": 0.95}

adapter = FunctionAdapter(
    fn=my_triage_agent,
    agent_id="triage-agent",
    version="1.0.0",
    model="gpt-4",
)
```

### A2A protocol agents

Agents that speak the [A2A protocol](https://a2a-protocol.org) (version 1.0) need no wrapper code. Point the adapter at the agent; it reads the Agent Card, picks the JSON-RPC interface and calls `SendMessage`:

```python
from a2a_spec import A2AAdapter

adapter = A2AAdapter(
    url="https://triage.example.com",   # or the full agent-card.json URL
    agent_id="triage-agent",
    headers={"Authorization": "Bearer $TOKEN"},
)
```

The input dict is sent as a structured `data` part (`text_field="message"` sends that field as text instead). Structured `data` parts in the reply become the output fields and text parts are joined under `"text"`; `json_text=True` parses a text-only reply that is a JSON object. Failed, rejected or input-required tasks raise an error with the agent's status message. The agent version from the card is stored in each snapshot. The adapter is tested against a server built with the official `a2a-sdk`.

### HTTP endpoints

```python
from a2a_spec import HTTPAdapter

adapter = HTTPAdapter(
    url="http://localhost:8000/triage",
    agent_id="triage-agent",
    version="1.0.0",
    headers={"Authorization": "Bearer $TOKEN"},
    timeout=30.0,
)
```

### LangChain runnables

```python
from a2a_spec import LangChainAdapter
from langchain_core.runnables import RunnableLambda

chain = RunnableLambda(lambda x: {"category": "billing", "summary": x["message"], "confidence": 0.9})

adapter = LangChainAdapter(
    runnable=chain,
    agent_id="triage-agent",
    version="1.0.0",
)
```

### Custom adapters

```python
from a2a_spec import AgentAdapter, AgentMetadata, AgentResponse

class MyCrewAIAdapter(AgentAdapter):
    def get_metadata(self) -> AgentMetadata:
        return AgentMetadata(agent_id="my-crew-agent", version="1.0")

    async def call(self, input_data: dict) -> AgentResponse:
        result = await my_crew.kickoff(input_data)
        return AgentResponse(output=result.dict())
```

## CLI Reference

| Command | Description |
|---------|-------------|
| `a2aspec init [DIR]` | Scaffold a new a2a-spec project with examples |
| `a2aspec record` | Record live agent outputs as snapshots |
| `a2aspec test --replay` | Validate snapshots against specs (deterministic, zero LLM calls) |
| `a2aspec test --live` | Validate live agent outputs against specs |
| `a2aspec infer --producer A --consumer B --source FILE:FN` | Generate a spec from the fields the consumer reads |
| `a2aspec diff` | Compare recorded snapshots against their committed version |
| `a2aspec diff --agent NAME --base REF` | Diff one agent against a git revision |
| `a2aspec skill [--dir DIR]` | Export the bundled agent skill |
| `a2aspec pipeline test FILE` | Test a multi-agent pipeline DAG |
| `a2aspec --version` | Show version |

→ See [docs/cli-reference.md](docs/cli-reference.md) for full options and flags.

## CI Integration

a2a-spec is designed for CI-first workflows. Record locally with your API keys; test in CI against committed snapshots — no secrets required in CI.

```yaml
# .github/workflows/a2a-spec.yml
name: Agent Contract Tests
on: [push, pull_request]

jobs:
  spec-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install a2a-spec
      - run: a2aspec test --replay
```

**Output formats:**

| Format | Flag | Use Case |
|---|---|---|
| Console (Rich) | `--format console` | Local development |
| Markdown | `--format markdown` | PR comments |
| JUnit XML | `--format junit` | CI test reporters |
| GitHub Annotations | `--format github` | Inline PR annotations |

→ See [docs/ci-integration.md](docs/ci-integration.md) for GitHub Actions, Jenkins, and more.
